# Локальный пример: данные → обучение → новая строка

Этот CLI показывает полный путь для GLiNER2.5: проверка JSONL, явные
символьные границы, полное дообучение или LoRA, сохранение весов, выбор по dev
и применение к новому тексту. Это **отдельный переносимый учебный рецепт**.
Сохраненные числа статьи находятся в `results/`; новые команды не объявляются
точным воспроизведением всех прежних запусков.

## Окружение

Python 3.12 и отдельное виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Установите подходящую для своей системы сборку PyTorch по
[официальной инструкции](https://pytorch.org/get-started/locally/), затем:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

API закреплены: `gliner2==2.1.0`, `transformers==5.22.1`, `peft==0.21.2`.
Текущая локальная техническая проверка использовала PyTorch 2.15.0+cpu.
Основные конфигурации `configs/full.json` и `configs/lora.json` предполагают
CUDA с поддержкой BF16. В первоначальном эксперименте обучение GLiNER
выполнялось на RTX 3090 24ГБ; это не гарантия достаточности любой другой машины.

База - `fastino/gliner2.5-multi-v1`, ревизия
`cf5593a5d45e3bbf204b9df621b13b1c0cf25ee3`. При первом обучении или загрузке
LoRA скрипт скачает именно этот публичный snapshot и проверит SHA256 весов.
Для уже сохраненной базы есть `--model models/base`. Базовые веса не входят
в Git-репозиторий; лицензия модели указана в ее
[карточке](https://huggingface.co/fastino/gliner2.5-multi-v1).

## Формат данных и своих типов

В `data/schema.json`:

- `names` переводит постоянную метку, например `PRIVATE_PRICE`, в имя запроса модели;
- `descriptions` задает описание каждого такого имени.

В JSONL одна строка содержит `id`, `text` и `spans`:

```json
{"id":"example-1","text":"Цена 10 EUR.","spans":[{"label":"PRIVATE_PRICE","start":5,"end":11,"text":"10 EUR"}]}
```

Координаты в символах Python, интервал полуоткрытый: `text[5:11] == "10 EUR"`.
Отрицательная запись имеет явное `"spans": []`. Отсутствующая разметка не
принимается за отрицательный пример. Повторяющаяся цитата размечается
конкретными координатами каждого нужного вхождения.

Для другой предметной области замените **схему и три JSONL**, сохранив роли:
train для весов, dev для выбора, test для итоговой независимой оценки.
Варианты одного исходного сюжета распределяйте между частями целыми семьями.
Скрипт дополнительно запрещает точные совпадения train/dev ID и текстов,
но эта проверка не доказывает отсутствия смысловых дубликатов.

Посмотреть фактический формат GLiNER без загрузки модели:

```bash
python src/ner_finetune.py prepare \
  --data data/crm/train.jsonl --schema data/schema.json \
  --output outputs/prepared/train-gliner.jsonl
```

Он проверит все записи, затем создаст `input`, `output.entities` и
`entity_descriptions`. Все типы присутствуют даже у отрицательной записи;
семейства и другие служебные поля во вход модели не попадут.

## Обучение

```bash
python src/ner_finetune.py train \
  --data data/crm/train.jsonl --schema data/schema.json \
  --config configs/lora.json --output outputs/lora --device cuda
```

Для полного дообучения замените конфигурацию на `configs/full.json` и каталог
на `outputs/full`. Команда принимает исходный JSONL и выполняет тот же
`to_example()` внутри; предварительная команда `prepare` нужна для просмотра
и проверки экспорта, а не для редактирования скрытого промежуточного файла.

Часть кода, соответствующая этой цепочке:

```python
schema = read_schema("data/schema.json")
rows = read_rows("data/crm/train.jsonl", schema)
examples = [to_example(row, schema) for row in rows]

# trainer создается из AutoExtractor и TrainingConfig в команде train
trainer.train(train_data=examples)
```

Полное дообучение обновляет все веса. LoRA замораживает базу, включая
слои извлечения сущностей, и обучает только A/B на `encoder.query/value`:
`r=16`, `alpha=32`, `dropout=0.05`. Список обучаемых параметров проверяется кодом.

Веса сохраняются после каждой полной эпохи в
`outputs/lora/checkpoint-epoch-1`, `checkpoint-epoch-2`, `checkpoint-epoch-3`.
Для LoRA это адаптер, который требует исходную базу. Для полного дообучения
каждая версия содержит модель целиком и занимает заметно больше места.
`recipe.json` хранит схему, вид checkpoint, выбранную базу и контрольные
суммы весов. Эти checkpoints не содержат полного состояния optimizer/RNG
для точного продолжения прерванного обучения.

Каталог запуска должен отсутствовать. На ошибке записывается `status=failed`;
OOM не пропускает документ. При завершении проверяется, что все примеры
обработаны во всех эпохах. На каждом батче проверяются реальные преобразования
символьных координат в targets и обратно. Вход длиннее
`max_encoded_tokens` останавливает запуск без обрезки.

## Выбор сохраненной версии и порога на dev

```bash
python src/ner_finetune.py select \
  --run outputs/lora --dev data/crm/dev.jsonl \
  --output outputs/lora-selection --device cuda
```

Для каждой сохраненной эпохи один раз получаются кандидаты dev. По этим
сохраненным кандидатам перебираются пороги 0.05–0.95. Выбор: максимальный
точный micro-F1, затем более ранняя эпоха и больший порог. `selection.json`
содержит выбранный checkpoint, порог и контрольную сумму его рецепта;
`scores.json` сохраняет всю сетку, JSONL - исходных кандидатов.

**Не передавайте test в `--dev`.** Утилита проверяет совпадения с train, но не
может определить роль произвольно названного файла. Результаты на dev не
являются итоговым качеством на test.

## Применение к новому тексту

Измените `examples/inference.txt`, затем:

```bash
python src/ner_finetune.py predict \
  --selection outputs/lora-selection/selection.json \
  --text-file examples/inference.txt --device cpu
```

Здесь загружается выбранный checkpoint. Адаптер LoRA объединяется с базой;
GLiNER возвращает кандидаты, применяются порог и разрешение пересечений.
Скрипт выводит исходный текст, типы/границы/score и строку с масками. Цифры
в stdout будут настоящими предсказаниями ваших весов; ожидаемый ответ не
подставляется.

Если сохраненную версию и порог выбрали отдельно, их можно задать явно:

```bash
python src/ner_finetune.py predict \
  --checkpoint outputs/lora/checkpoint-epoch-3 --threshold 0.90 \
  --text-file examples/inference.txt --device cpu
```

0.90 в этой команде - пример явного параметра, не рекомендация для нового
набора. Для значения из dev используйте `--selection`. Подмена порога при
одновременном `--selection` запрещена. Инференс также проверяет длину входа
по лимиту сохраненного рецепта; обработка окон - отдельный эксперимент.

## Что проверено и чем пример отличается от опыта

Перед публикацией выполнены восемь тестов без моделей: точные координаты,
повторные вхождения, отрицательные примеры, полнота схемы, дубли ID,
пересечения, декодирование/маски и контроль целостности checkpoint.
Экспортированы все 5 000 исходных train-записей. Дополнительно на существующей
закрепленной базе выполнен один реальный CPU-шаг LoRA на новом маленьком
учебном наборе: веса изменились, адаптер сохранился, заново загрузился и
дал корректные по структуре spans и маску. Это техническая проверка, не
оценка качества модели после одного шага.

Этот компактный рецепт использует обычное перемешивание батчей, а исходный
опыт - группировку по длине. При равном F1 исходный опыт также учитывал
маски публичных целей; здесь tie-break упрощен до эпохи и порога.
Инференс примера выполняется в FP32 и не воспроизводит опубликованные
BF16-замеры задержки. Полная GPU-серия и девятнадцать порогов по всем эпохам
этого нового учебного скрипта заново не прогонялись. Поэтому опубликованные
метрики относятся к сохраненным экспериментам, а не к обещанным результатам
повторного запуска этих команд.
